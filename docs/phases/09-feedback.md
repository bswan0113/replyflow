# 9단계 — 관리·피드백

옛 파이프라인의 9단계(관리)와 10단계(피드백)를 하나로 합친 단계다. 결국 하는 일은 하나다: 독자 반응(정량+정성)을 취합해 보고하고, 방향을 수정할지 말지 결정한다. `CLAUDE.md`의 10행은 이 단계에 통합되어 별도 진입점이 없다.

## 목표

게시된 회차의 반응을 정량(조회수·댓글수·선호작수)과 정성(댓글 내용) 양쪽으로 취합해 사용자에게 보고하고, 방향 수정이 필요한지 결정한다. 필요하면 이미 확립된 세계관/플롯/캐릭터 확장 절차로 라우팅한다.

## 진입

`.claude/skills/novel-feedback/SKILL.md`를 호출한다. 이 단계는 연재 기간 내내 **반복적으로 재진입**된다 — 한 번 통과하고 끝나는 단계가 아니다.

## `project.yaml` 처리 (반복 재진입)

`status`는 9에 도달한 이후로는 계속 9를 유지한다 — 연재가 이어지는 한 "관리·피드백 루프"에 있다는 뜻이다. 매 라운드(예: 몇 화마다 한 번씩)마다 `stage_history`에 `stage: 9` 항목을 새로 추가하고 `note`에 그 라운드에서 무엇을 확인하고 어떻게 결정했는지 요약을 남긴다. 여러 개의 `stage: 9` 항목이 쌓이는 것이 정상이다.

## 절차

1. **정량 데이터 수집**: 회차별 조회수/댓글수/선호작수 등. 로컬 세션이 실제로 브라우저 조작 도구를 가지고 있다면 직접 플랫폼에서 조회한다. 없다면 사용자가 직접 숫자를 불러준다. `projects/<slug>/07-feedback/stats.md`에 회차별로 기록한다.
2. **정성 피드백 수집**: 독자 댓글 등 텍스트. 사용자가 직접 붙여넣거나, 브라우저 조작 도구가 있다면 세션이 직접 가져온다. `feedback-analyst` 서브에이전트를 호출해 칭찬/비판/떡밥예측/오류지적 등으로 분류·요약받는다.
3. **보고**: 1~2에서 모은 정량+정성 요약을 사용자에게 보여준다.
4. **결정**: 사용자가 방향 수정이 필요한지 결정한다.
   - **불필요**: 이번 라운드를 종료하고 6단계(집필)로 복귀한다.
   - **필요, 세계관/플롯/캐릭터 범위**: 어느 영역인지 확인한 뒤 `worldbuilder-update`/`plot-architect-update`/`character-designer-update` 중 해당하는 서브에이전트를 호출해 제안을 받고, 사용자 승인 후 반영한다 — 이미 3·4단계에서 확립된 절차를 그대로 재사용한다 (1·3·4단계 순환).
   - **필요, 근본적 전환(예: 장르 자체를 바꿔야 함)**: 이건 위 세 서브에이전트의 범위를 넘는 드문 경우다. 전용 메커니즘을 따로 만들지 않고, 사용자와 직접 논의해 `01-idea/synopsis.md`를 수정한다.
5. **기록**: `projects/<slug>/07-feedback/log.md`에 이번 라운드를 기록한다 — 수집한 데이터 요약, 결정, 반영된 변경사항(있다면 어느 update 서브에이전트를 거쳤는지).
