# 4단계 — 캐릭터 생성

## 목표

캐릭터 초안을 형식 제약 없이 확립하고, 이후 작품이 진행되는 동안(어느 단계의 세션에서든) 필요할 때마다 보완·수정 제안을 받아 사용자 승인 하에 반영한다. 세계관·플롯과 마찬가지로 한 번에 완벽한 설계를 기대하지 않는다.

## 초기설계 (Init)

### 입력
- `projects/<slug>/01-idea/synopsis.md`
- `projects/<slug>/02-world/worldbuilding.md` (있는 만큼)
- `projects/<slug>/04-outline/plot.md` (있는 만큼)

### 진행 방식
엄격한 절차를 강제하지 않는다. Claude/Codex 어느 쪽이 초안을 제안하든, 사용자가 직접 캐릭터를 먼저 던지든 자유롭게 진행한다. 아래 최소요건만 충족하면 통과로 본다.

### 최소요건
`projects/<slug>/03-characters/characters.md`에 다음이 담겨 있어야 한다:
- 주인공 프로필 (핵심 욕망/결핍, 성장 아크)
- 핵심 조연·빌런 프로필 (역할, 주인공과의 관계)
- 관계도 (텍스트 형태로 충분 — 별도 그래프 툴/포맷 불필요)

## 확장 (Update)

캐릭터도 세계관·플롯과 동일하게, 집필이 진행되며 계속 조정될 가능성이 높은 영역이다. 확장 절차는 4단계에만 묶여있지 않고, 프로젝트 진행 중 어느 단계의 세션에서든 호출할 수 있다.

### 트리거
- 사용자가 직접 "캐릭터를 수정/추가하고 싶다"고 요청
- 다른 단계의 세션(예: 집필 중인 세션)이 진행하다가 기존 캐릭터 설정과 모순되는 상황이나, 새 인물이 필요하다고 판단했을 때
- 세계관·플롯 확장으로 설정이 바뀌어 캐릭터 설정 일부가 더 이상 맞지 않게 됐을 때

### 절차
1. 호출 세션이 `character-designer-update` 서브에이전트를 부른다. 이 서브에이전트는 현재 `characters.md`와 (있다면) 계기가 된 맥락을 읽고, 아래 형식의 **제안만** 만들어 반환한다. 파일을 직접 수정하지 않는다.
   ```
   ## 제안: <한 줄 요약>
   - 왜 필요한가: ...
   - 무엇을 바꾸는가: <구체적으로 추가/수정할 캐릭터 정보>
   - 어디에 반영: characters.md의 어느 섹션
   ```
2. 호출 세션은 이 제안을 사용자에게 그대로 보여주고 승인을 받는다. **승인 없이는 절대 파일을 수정하지 않는다.**
3. 승인을 받으면 호출 세션이 직접 `characters.md`를 수정하고, `projects/<slug>/03-characters/changelog.md`에 한 줄을 추가한다: `<날짜> — <요약> — <사유>`.

## 산출물

- `projects/<slug>/03-characters/characters.md`
- `projects/<slug>/03-characters/changelog.md` (확장이 발생할 때마다 추가)
