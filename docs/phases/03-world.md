# 3단계 — 세계관

## 목표

세계관 초안을 형식 제약 없이 확립하고, 이후 작품이 진행되는 동안(어느 단계의 세션에서든) 필요할 때마다 보완·수정 제안을 받아 사용자 승인 하에 반영한다. 한 번에 완벽한 설계가 나올 것을 기대하지 않는다 — 초기설계는 가볍게 시작하고, 확장은 반복적으로 이뤄지는 것을 전제로 한다.

## 초기설계 (Init)

### 입력
- 사용자가 직접 던지는 세계관 뼈대(있다면)
- `projects/<slug>/01-idea/synopsis.md` (1단계 시놉시스)

### 진행 방식
엄격한 절차를 강제하지 않는다. Claude가 먼저 초안을 제안하든, Codex가 하든, 사용자가 스스로 뼈대를 던지고 그걸 다듬어가든 상관없다. 여러 방식을 시도해보고 결과가 좋은 쪽으로 진행해도 된다. 아래 최소요건만 충족하면 통과로 본다.

### 최소요건
`projects/<slug>/02-world/worldbuilding.md`에 다음이 담겨 있어야 한다:
- 장르에 맞는 핵심 설정 (시대/장소/사회구조 등, 장르가 요구하는 만큼만)
- 스토리 진행에 필요한 시스템 규칙이 있다면 그 규칙 최소 1편 (예: 마법 체계, 헌터 등급, 기업 위계 등 — 없는 장르라면 생략 가능)
- 1단계 시놉시스와 모순되지 않는지 자체 점검 한 줄

## 확장 (Update)

세계관은 캐릭터·플롯·집필이 진행되면서 계속 보완될 것으로 예상되는 영역이다. 그래서 확장 절차는 3단계에만 묶여있지 않고, 프로젝트 진행 중 어느 단계의 세션에서든 호출할 수 있다.

### 트리거
- 사용자가 직접 "세계관 보완/수정하고 싶다"고 요청
- 다른 단계의 세션(예: 집필 중인 세션)이 진행하다가 기존 세계관 설정과 모순되는 새 요소가 필요하다고 판단했을 때
- 회차 전개상 아직 설명되지 않은 시스템 규칙이 필요하다고 판단했을 때

### 절차
1. 호출 세션이 `worldbuilder-update` 서브에이전트를 부른다. 이 서브에이전트는 현재 `worldbuilding.md`와 (있다면) 계기가 된 맥락(예: 문제가 된 회차 원고 일부)을 읽고, 아래 형식의 **제안만** 만들어 반환한다. 파일을 직접 수정하지 않는다.
   ```
   ## 제안: <한 줄 요약>
   - 왜 필요한가: ...
   - 무엇을 바꾸는가: <구체적으로 추가/수정할 문단>
   - 어디에 반영: worldbuilding.md의 어느 섹션
   ```
2. 호출 세션은 이 제안을 사용자에게 그대로 보여주고 승인을 받는다. **승인 없이는 절대 파일을 수정하지 않는다.**
3. 승인을 받으면 호출 세션이 직접 `worldbuilding.md`를 수정하고, `projects/<slug>/02-world/changelog.md`에 한 줄을 추가한다: `<날짜> — <요약> — <사유>`.

## 산출물

- `projects/<slug>/02-world/worldbuilding.md`
- `projects/<slug>/02-world/changelog.md` (확장이 발생할 때마다 추가)
