# 에세이 작성 하네스

블로그용 짧은 에세이 한 편을 끝까지 완성하기 위한 가벼운 진행 가이드다.
무거운 상태머신이나 서브에이전트, 검증 게이트는 쓰지 않는다 — 매 단계는 그냥 사용자와의 대화다.

## 저장 위치

에세이 한 편 = `essay-harness/essays/<slug>.md` 파일 하나.
파일 맨 위에 아래 frontmatter만 유지한다.

```yaml
---
title: 가제
status: idea # idea -> draft -> revision -> ready
---
```

`status`가 그 에세이의 유일한 진행 상태 표시다. 별도 로그나 changelog 파일을 만들지 않는다.

새 에세이를 시작할 때는 제목 후보로 slug를 정하고 (예: `essays/ai-를-쓰면서-잃는-것.md`) 위 frontmatter만 채운 빈 파일을 만든다.

## 진행 방식

사용자가 `/essay`를 부르면, 대상 에세이 파일이 있는지 먼저 확인한다.

- 파일이 없으면 → **소재구상**부터 시작.
- 파일이 있으면 → frontmatter의 `status`를 보고 해당 단계부터 이어간다.

각 단계는 산출물을 그 에세이 파일에 직접 반영하고, 사용자가 다음 단계로 넘어가도 좋다고 판단되면 `status`를 갱신한다. 단계를 건너뛰거나 되돌아가는 것도 자유롭다 — 강제되는 순서는 없다.

### 1. 소재구상 (status: idea)

목표: 무엇에 대해, 누구에게, 어떤 한 가지 요점을 전달할지 정한다.

- 사용자가 던진 주제/아이디어를 구체적인 각도로 좁히도록 함께 이야기한다.
- 다음 세 가지가 한 문단으로 정리되면 충분하다: 주제, 핵심 요점(한 문장), 예상 독자.
- 파일에 `## 기획` 섹션으로 이 요약을 적는다.
- 사용자가 동의하면 `status: draft`로 바꾸고 다음 단계로.

### 2. 초안 (status: draft)

목표: 처음부터 끝까지 읽히는 완성된 초안 한 편.

- 기획 섹션을 바탕으로 전체 초안을 작성한다. 완벽함보다 완주가 목표.
- 분량이나 톤에 대해 사용자 선호가 있으면 반영하고, 없으면 짧은 블로그 글(원고지 기준 대략 A4 1장 안팎)을 기본으로 삼는다.
- 파일에 `## 초안` 섹션으로 본문을 적는다.
- 사용자가 초안을 보고 만족하면 `status: revision`으로.

### 3. 퇴고 (status: revision)

목표: 불필요한 부분을 덜어내고 문장과 흐름을 다듬는다.

- 사용자와 함께 초안을 다시 읽으며 늘어지는 부분, 어색한 문장, 논리 비약을 짚는다.
- 요청받은 수정만 반영한다 — 요청 없이 톤이나 구조를 임의로 크게 바꾸지 않는다.
- 여러 번 오갈 수 있다. 만족스러운 버전이 나오면 같은 섹션(`## 초안`, 필요하면 이름을 `## 본문`으로 바꿔도 됨)을 최종본으로 덮어쓴다.
- 사용자가 됐다고 하면 `status: ready`로.

### 4. 발행준비 (status: ready)

목표: 그대로 복사해서 올릴 수 있는 상태로 마무리한다.

- 제목 후보 2~3개를 제안한다.
- 원하면 한두 문장짜리 요약/메타 설명을 만들어준다.
- 본문에 남은 플랫폼 무관 정리(오탈자, 마크다운 서식 등)를 확인한다.
- 특정 플랫폼(예: 브런치, 티스토리, 미디엄)에 맞춘 서식 조정이 필요하면 사용자에게 물어보고 반영한다.
- 이 단계를 마치면 에세이는 완성된 것으로 본다. 별도의 "발행" 자동화는 하지 않는다 — 실제 게시는 사용자가 직접 한다.

## 하지 않는 것

- 여러 에세이를 오케스트레이션하는 상위 상태 파일 (project.yaml 류) 없음.
- 단계마다 서브에이전트를 호출하지 않음 — 전부 메인 대화에서 처리.
- changelog나 버전 이력 파일을 따로 두지 않음. 필요하면 git 커밋 이력이 그 역할을 한다.
- 단계 통과를 판정하는 별도 "리뷰어" 절차 없음 — 다음 단계로 넘어갈지는 사용자와의 대화로 결정한다.
